# XZ Done - 归档版本计划

参数: `$ARGUMENTS`

## 辅助脚本

**脚本**：`xz-tools.py`

插件启用时 `bin/` 目录自动加入 PATH，直接作为命令调用即可（不需要 `python3` 前缀，也不需要绝对路径）。脚本在**当前工作目录**下操作 `.xz_planning/`。

---

## 参数校验与分流

`$ARGUMENTS` 为空 → **立即停止**：

> 缺少参数。用法: `/xz-done N`（归档单个版本）或 `/xz-done all`（全部强制归档）
> 示例: `/xz-done 1`、`/xz-done 1.5`、`/xz-done all`

按参数分两条路径走：

| 参数 | 走哪条 |
|------|--------|
| 合法版本号（正整数，或小数如 `1.5`） | **A 路径**：单版本归档，三道闸门都要过 |
| `all`（不分大小写） | **B 路径**：全量强制归档，跳过闸门 |
| 其他 | 停止，按上面的用法提示 |

---

# A 路径：单版本归档 `/xz-done N`

### 第一步：检查状态

```bash
xz-tools.py parse $ARGUMENTS
```

检查版本 N 是否存在，以及 todolist 完成情况。

**同时读 PLAN 头部 `> 状态:`** —— 脚本只按 todolist 勾选算进度，**不看这个字段**，所以这里必须自己读一次：

| 状态 | 处理 |
|------|------|
| `待手动执行` | **不许归档**，提示「这个版本走手动路径，代码还没贴完。先跑 `/xz-manual N` 生成清单并贴码校验」 |
| `待闭环测试` | **不许直接归档**，提示「`/xz-manual` 校验过了，但闭环测试还没跑。先跑 `/xz-exec N`，它会直接做闭环验证」。用户坚持要跳过测试归档 → 让他明确回一句「确认跳过闭环测试归档」才放行，并在归档记录里留痕 |
| 其他 | 正常进第二步 |

### 第二步：判断是否可归档

- **全部 `[x]`** → 直接进入归档流程
- **存在 `[ ]`** → 以纯文本警告并提问（禁用 AskUserQuestion）：

  > 版本 N 还有 X 条未完成任务。回复：
  >   1) 强制归档 — 忽略未完成条目，直接归档
  >   2) 返回继续执行 — 执行 /xz-exec N 完成剩余任务

  回复「返回继续执行」则停止归档；「强制归档」则继续；其他输入按内容响应。

### 第三步：记录归档时间

**获取当前时间：**

```bash
date "+%Y-%m-%d %H:%M:%S"
```

**移动目录之前**，在 N-PLAN.md 的变更记录中追加：

```
- YYYY-MM-DD HH:mm:ss 归档完成
```

同时更新 `> 最后更新:` 为当前精确时间。

### 第四步：执行归档

运行辅助脚本（纯文件移动，不涉及任何 git 操作）：

```bash
xz-tools.py complete $ARGUMENTS
```

该脚本会把 `.xz_planning/phases/N.xxx/` 移动到 `.xz_planning/archive/N.xxx/`，并自动重建 STATE.md。

### 第五步：输出归档结果

显示归档摘要：版本号、需求名称、完成条数、归档时间。

然后以纯文本输出下一步选项：

> 版本 N 已归档。下一步: /xz-status（查看所有版本状态）/ /xz-plan N（创建新版本计划）

# B 路径：全量强制归档 `/xz-done all`

**「强制」的含义**：跳过 A 路径的三道闸门（`待手动执行`、`待闭环测试`、有未完成条目），`phases/` 下**所有**版本一律归档。

**但仍然要先列清单、等用户确认一次** —— 这是一次性移走全部计划目录，不能闷头就做。

### 第一步：列出待归档清单

```bash
xz-tools.py list-phases
```

返回 JSON：`count` 是版本数，`phases` 是每个版本的 `version` / `name` / `progress` / `status`，`skipped` 是 phases 下不符合 `N.名称` 格式、**不会被动**的目录。

- **`count` 为 0** → 停止，提示「phases 下没有可归档的版本，无需操作」（若 `skipped` 非空，一并说明这些目录不是版本目录，不会动）
- **`count` > 0** → 进第二步

### 第二步：展示清单 + 一次确认（纯文本，禁用 AskUserQuestion）

把清单摆出来，**未完成的和状态异常的要标出来**，让用户看清楚自己在归档什么：

```
即将强制归档 phases 下全部 3 个版本：

  版本   需求名              进度    状态
  1      用户注册登录         3/3     ✅ 已完成
  1.5    历史开关            1/2     ⚠️ 未完成
  2      订单软删除          0/2     ⚠️ 待手动执行

⚠️ 其中 2 个版本没做完，all 会一律强制归档，不做拦截。
（phases 下的 `草稿备忘` 不是版本目录，不会动）

确认归档全部？回复：
  1) 确认 — 全部移入 archive/
  2) 取消 — 什么都不做
```

回复「取消」或其他否定表达 → 停止，什么都不做。回复「确认」 → 进第三步。

### 第三步：逐个记录归档时间

```bash
date "+%Y-%m-%d %H:%M:%S"
```

**移动目录之前**，对清单里**每一个**版本的 `N-PLAN.md` 都追加变更记录并更新 `> 最后更新:`：

```
- YYYY-MM-DD HH:mm:ss 归档完成（/xz-done all 批量强制归档）
```

没有 `N-PLAN.md` 的目录（`plan_exists` 为 false）跳过这步，不报错。

### 第四步：执行批量归档

```bash
xz-tools.py complete all
```

脚本会按版本号从小到大逐个移入 `archive/`，最后重建一次 STATE.md。返回 JSON 的 `count` 是实际归档数，`archived` 是每条的移动记录。

### 第五步：输出结果

```
已归档 3 个版本：
  1     用户注册登录     → archive/1.用户注册登录
  1.5   历史开关        → archive/1.5.历史开关
  2     订单软删除      → archive/2.订单软删除

phases/ 已清空。
```

若 `skipped` 非空，补一行说明这些目录保留在 `phases/` 下。

然后：

> 下一步: /xz-status（查看所有版本状态）/ /xz-plan 1 需求描述（开新版本）

---

## 关键规则

1. **不执行任何 git 操作** — 只做文件移动和 STATE 更新
2. **A 路径未完成需确认** — 有 `[ ]` 条目时必须警告并等待确认
3. **B 路径必须先列清单再确认** — `all` 跳过的是完成度闸门，**不是用户确认**；没展示清单就直接 `complete all` 属于违规
4. **归档时间精确** — 变更记录和 STATE.md 中的完成时间精确到时分秒，`all` 路径每个版本都要写
5. **非版本目录不动** — `phases/` 下不符合 `N.名称` 格式的目录原样保留，并在输出里说明
