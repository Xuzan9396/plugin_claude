# XZ Manual - 手动执行清单与校验

参数 `$ARGUMENTS`：第一个空格前是版本号 N，后面可选 `sync`。
N 为空或不是合法版本号（正整数，或小数如 1.5）→ **立即停止**，提示 `用法: /xz-manual N`。

**脚本**：`xz-tools.py`（`bin/` 已在 PATH，直接调用，在当前目录操作 `.xz_planning/`）。

> ⚠️ **全程禁用 AskUserQuestion 等提问工具**：Claude Code 已知 bug——同一轮回复中提问弹窗之前的文本会被终端吞掉，用户会看不到清单。所有确认一律用纯文本提问，等用户回复。

## 这个 skill 管什么

「手动执行」是 `/xz-plan` 第 5 步的第 3 条路径：**AI 只写清单不碰源码，用户自己照着贴码**，图的是自己掌握代码写到哪儿了。这条路径的全部环节都在本 skill：

```
/xz-plan N → 选路径 3 → PLAN 状态置「待手动执行」
                              ↓
              /xz-manual N        生成 N-MANUAL.md（改动地图 + 逐块成品代码）
                              ↓
                          人工逐块贴码
                              ↓
              /xz-manual N        校验比对 → 闸门确认 → 状态置「待闭环测试」
                              ↓
              /xz-exec N          跑闭环测试（直接进第七步，不重复实现）

中途改了计划：/xz-update-plan N → 提示 → /xz-manual N sync  同步清单
```

## 模式判断（读到 PLAN 后立即判断）

```bash
xz-tools.py parse $ARGUMENTS
```

从返回 JSON 取 `phase.plan_file`，读 N-PLAN.md 的 `目标` / `上下文` / `约束` / `技术方案` / `任务清单`（含每条 改动详情）。版本不存在 → 提示先跑 `/xz-plan N`。

| 情况 | 模式 |
|------|------|
| 带了 `sync` 参数 | **同步模式** — 按计划变更增删改清单里的块 |
| 没有 `N-MANUAL.md` | **生成模式** — 从头写一份 |
| 有 `N-MANUAL.md`，没带 `sync` | **校验模式** — 认为用户已贴完码，逐条比对 |

PLAN 状态不是 `待手动执行` 且没有 `N-MANUAL.md` → 停止，提示「版本 N 走的不是手动路径，直接跑 `/xz-exec N` 即可」。

## 改动 2 ｜ 新建 `src/util/retry.go`
做什么：新增重试工具 Retry()，供登录失败时调用。整个文件新建，不动其他文件。
```go
package util

import "time"

// Retry 执行 fn，失败则重试，最多 attempts 次，每次间隔 delay。
// 例: Retry(3, 2*time.Second, login) → 失败时最多试 3 次，总耗时约 0s/2s/4s 三档。
func Retry(attempts int, delay time.Duration, fn func() error) error {
	var err error
	for i := 0; i < attempts; i++ {
		// fn 成功立即返回；失败记录 err 进入下一轮
		if err = fn(); err == nil {
			return nil
		}
		time.Sleep(delay) // 每轮间隔: delay=2s → 第2次在2s后、第3次在4s后
	}
	return err // 全部失败，返回最后一次的错误
}
```

### 版面三件套（少一样即违规）

顶部**改动地图**总表、每块 `═══ 改动 i/n ═══` 分隔线、末尾**贴完自查**块。让人动手前看到全景、贴的过程中知道进度、贴完能自查。

- 每块标题 = 操作 + 文件 + 处数（单处写行号或函数名）；「做什么」一句 = 效果 + 边界「仅动这几处，其他不改」

### 每个改动点怎么写（代码块一律是最终成品，复制即用）

- **改** = 三段标识块 `========= v计划号 真实改动标题 before|start|end ===========`：`before` 放真实原文锚点，`start`~`end` 之间放改后的最终代码。只给最小必要上下文，**禁止把未改的方法或整文件带出来**。
- **增** = 新建文件给从第一行到最后一行的整文件（含 package / import / 注释）。往已有文件插内容算「改」，同样走三段标识块。
- **删** = 贴出要删的完整原文；需要定位可补一小段前后文，不带无关大段。
- **禁止任何省略**：不得出现 `...`、`// 略`、`// 其余不变`、`// 完整内容见 PLAN`、`<同上>`、伪代码、自然语言占位。
- **函数方法必带注释和案例**：片段里出现函数或方法，上方必须有用途注释 + 一个直观案例（输入 / 场景 / 结果）。匿名函数和单行闭包除外。
- **关键逻辑注释带示例数据**：计算 / 拼接 / 转换 / 解析 / 分支判断处须有注释说明在干嘛；凡涉及数据格式、字符串拼接、计算结果的，注释要带示例数据，如 `// key = uid + "_" + date → "1001_20260610"`、`// 金额分转元: 1250 → "12.50"`。
- 上面模板里的代码只是格式示例，实际一律写真实完整代码。

### 写完自查

代码块含省略标记、修改场景带了整文件、函数方法上方缺注释或案例、修改缺 `v计划号` 标识、格式拼接计算处缺示例数据注释、缺改动地图 / 分隔线没标 `i/n` / 缺贴完自查——**任一项即违规，必须补全重写**。

## 模式二：同步（`/xz-manual N sync`）

`/xz-update-plan N` 改过计划后引导过来。目的是让清单跟上计划，**不碰用户已经贴好的源码**。

1. 读 PLAN 现在的 任务清单，对照现有 `N-MANUAL.md` 的改动块，算出差异
2. **先展示同步草案再落地**（纯文本，等用户确认）：

```
MANUAL 同步草案（改版 K）：
  新增块：改动 5（对应新 todo #5 缓存失效）
  修改块：改动 2（todo #2 的 改动详情 变了，锚点和目标代码都要重写）
  删除块：改动 4（todo #4 已删）
  不动：  改动 1、3

回 `同步OK` 落地，或说明要调整的地方。
```

3. 确认后落地，四条规则：
   - **增删改一一对应** —— 改条目重写对应块；增条目追加或插入新块；删条目删掉对应块。todo 重编号了，MANUAL 块号跟着重排
   - **改版标识** —— 本次改版号 = 现有最大 `改版K` + 1（没有则为 1）。本次新增或修改的块，大分隔线标题后面加 `｜【改版K·新增｜需重新手动】` 或 `｜【改版K·修改｜需重新手动】`，让用户一眼挑出要重贴哪几块
   - **头部改版记录** —— 文件顶部引导注释区维护「改版记录」，每次追加一行 `- 改版K YYYY-MM-DD HH:mm:ss 新增X块/修改Y块/删除Z块`
   - **块格式与自查沿用模式一**，一个字不放松

## 模式三：校验（人工贴完码之后）

**目的是让用户掌握代码写到哪儿了，不是「AI 永远不许碰代码」。** 本模式分三段，闸门前后行为完全不同：

- **闸门前** — AI **只读不写**：一致或等价的自动勾选不打扰，有问题的**只记录不动手**，保护手动成果不被静默覆盖
- **闸门** — 汇总全部差异**一次问清**，同时拿到后续修复的授权
- **闸门后** — 按用户选择补齐差异，然后交给 `/xz-exec N` 跑闭环，不再逐处询问

对齐方向是**文档跟着代码走**：手动实现等价但风格不同时，改 PLAN / MANUAL 去贴合手动代码，而不是反过来。

### 逐条比对，按一致程度分级

逐条读 任务清单 的 改动详情，用 Read 检查对应文件的实际改动：

| 结论 | 怎么处理 |
|------|------|
| **完全一致** — 代码已按 改动详情 改好 | 勾选 `[x]`，变更记录标「校验通过 #N」 |
| **轻微差异** — 语义达成、功能等价（变量名 / 注释 / 格式 / 等价写法不同，常见是用户自己的代码风格） | **保持手动现状不变**，照常勾选 `[x]`；**同步对齐文档**：把 PLAN 该条 改动详情 和 MANUAL 对应块改写成手动的实际实现；变更记录标「#N 手动实现，与计划等价，已对齐 PLAN/MANUAL（差异: …）」 |
| **严重错误 / 未落地** — 漏改、改错文件或位置、复制粘贴出错导致功能不符 | **不改、不勾**，记入待确认清单：问题描述 + 现状代码摘要 + 计划预期 |
| **无法判断** — 改动详情 与代码模糊到没法对照 | 同样记入待确认清单，注明判断不了的点 |

**问题点禁止边审边改**，必须全部攒到闸门一次性确认。

### 闸门：一次性确认

待确认清单非空 → 编号列出所有问题点，**一次问完**。**默认一律对齐原计划**，每项 `a` 固定是「按计划修正」，用户只需要挑出自己想保留的差异：

```markdown
以下 N 处与计划不一致，确认后我按你的选择处理：

1. #3 `src/auth/login.go` 超时未生效 — 手动只加了 Timeout 但写在 Do() 之后
   a. 按计划修正（推荐，与原计划对齐）  b. 保持现状并勾选（记为你指定的差异）  c. 跳过，我自己再改
2. #5 `src/util/retry.go` 未创建 — 文件不存在
   a. 按计划补建（推荐，与原计划对齐）  b. 跳过，我自己补

回复如 `1a 2b`，或 `全部默认`（= 全部按计划修正）。
确认后我会补齐差异并做语法检查，然后把状态转成「待闭环测试」，你再跑 /xz-exec N 做验证。
```

清单末尾必须带上最后那两行（`全部默认` 的含义 + 确认后会做什么），让用户知道**这是唯一一次打断**。

用户选定后才动手：

- **按计划修正** → 改完做语法检查再勾选，变更记录标「#N 经用户确认按计划修正」
- **保持现状** → 不动代码直接勾选，**并把 PLAN 改动详情 与 MANUAL 对应块改写成手动的实际实现**，标「#N 经用户确认保留手动实现，已对齐 PLAN/MANUAL」，**同时记进 PLAN 的 `## 约束`**（见下）
- **跳过** → 不动不勾，标「#N 待用户手动处理」

### 用户指定的差异必须留痕

凡是结论为「等价保留」或用户明确选了「保持现状」的条目，除了文档对齐，还要在 PLAN 的 `## 约束` 追加一行：

```
已确认保留手动实现：#3 `src/auth/login.go` 用早退代替嵌套 if（与计划写法不同，功能等价）。后续修复不得改回计划写法。
```

这行是给 `/xz-exec` 第七步看的——闭环修 bug 时不许把它改回去。

### 文档对齐代码

「等价保留」「确认保留手动实现」的条目，按实际代码改写 PLAN 的 改动详情（行号 / 现状摘要 / 改动点）和 MANUAL 对应块（格式沿用模式一，**只回写实际改动块，不把未改的方法整段带回**），做到 **源码 = PLAN = MANUAL 三者一致，且源码一行不动**。

### 校验完的走向

每条处理完更新 PLAN 的 `> 最后更新:` 与变更记录，然后：

| 状态 | 走向 |
|------|------|
| **条目全部勾选** | PLAN 头部 `> 状态:` 置为 **`待闭环测试`** → 跑 `xz-tools.py update-state` → 提示用户运行 `/xz-exec N` |
| **有「跳过，我自己改」的条目** | 状态**保持 `待手动执行`** → 出报告列出待处理条目，提示「处理完重新跑 `/xz-manual N`」 |

输出汇总：**校验通过 X 条 / 等价保留 Y 条 / 经确认修正 Z 条 / 跳过待手动 W 条**，逐条列结论。

条目全过时的输出：

```
校验完成：通过 X 条 / 等价保留 Y 条 / 经确认修正 Z 条
状态已转「待闭环测试」。下一步运行 /xz-exec N —— 它会直接跑闭环测试
（跑用例、修 bug、全量回归、出 N-TEST-REPORT.md），不会重复实现已经勾选的条目。
```

## 关键规则（命中任一即违规；细节回看对应模式）

| # | 规则 | 什么算违规 | 回看 |
|---|------|-----------|------|
| 1 | 生成和同步阶段绝不碰源码 | 模式一 / 模式二里改了源码或勾了 todo | 模式一 |
| 2 | 锚点来自真实代码 | `before` 段的原文是编的，没真 Read 过 | 模式一 |
| 3 | 代码块是复制即用的成品 | 出现 `...` / `略` / `其余不变` / 伪代码；修改块缺 `v计划号` 三段标识；修改场景带了整文件；函数方法上方缺注释或案例；格式拼接计算处缺示例数据注释 | 模式一 |
| 4 | 版面三件套齐全 | 缺改动地图、分隔线没标 `i/n`、缺贴完自查；改动地图行数与实际改动块对不上 | 模式一 |
| 5 | 同步先给草案再落地 | 没展示同步草案就直接改 MANUAL；改版标识或头部改版记录漏写 | 模式二 |
| 6 | 闸门前只读，问题攒到闸门 | 边审边改；分多次问用户 | 模式三 |
| 7 | 用户手动成果受保护 | 「保持现状」的写法没写进 PLAN `## 约束` 留痕；「跳过，我自己改」的条目被 AI 抢着实现——那正是用户明确要自己动手的部分 | 模式三 |
| 8 | 文档对齐代码，不是代码对齐文档 | 等价保留的条目改了源码去贴合计划，而不是改 PLAN / MANUAL 去贴合代码 | 模式三 |
| 9 | 状态流转不能断 | 全部勾选却没把状态置成 `待闭环测试`，或没提示用户跑 `/xz-exec N`——闭环测试会被跳过 | 模式三 |
