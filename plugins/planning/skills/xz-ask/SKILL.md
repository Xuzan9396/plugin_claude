# XZ Ask - 只回答，不动手

参数 `$ARGUMENTS`：用户的问题。为空 → 停止并提示 `用法: /xz-ask 你的问题`。

## 铁律：全程只读

**本 skill 内禁止任何写操作，一次都不行。**

禁止：

- Edit / Write / NotebookEdit —— 不改、不建、不删任何文件
- 任何改动状态的 Bash：`rm`、`mv`、`cp`、`mkdir`、`>` / `>>` 重定向、`git commit` / `git checkout` / `git apply`、包管理器安装、跑构建或部署脚本
- 动 `.xz_planning/` 下的任何东西

允许：`Read`、`Grep`、`Glob`，以及**只读**的 Bash（`git log`、`git diff`、`git status`、`ls`、`cat`、`grep`、`find`）。

**发现 bug 也只是说出来，不许顺手修。** 用户在本次调用中改口说「那你改一下」→ 停下，告诉他改代码请用 `/xz-exec` 或 `/xz-debug`，本 skill 不改。

## 怎么答

1. **第一句就是结论。** 不铺垫、不复述问题、不写「好问题」。
2. **涉及本仓库代码的结论必须先 Read 确认**，并带上 `file_path:line`。不许凭印象答。
3. **能一句说完就一句。** 要列举用短列表；只有用户明确要求详细时才展开。
4. **不知道就说不知道**，或说清楚要看什么才能回答。不编、不猜着说得像真的。
5. 问题有歧义先追问一句，纯文本问——**禁用 AskUserQuestion，它的弹窗会吞掉同一条回复里前面的文本。**

## 不许出现的话术

- 答完后追加「需要我帮你改吗？」——本 skill 改不了，问了是空头承诺
- 甩一大段完整代码当「建议改法」，那是变相改代码。说清楚改哪儿、改成什么效果即可，引用片段控制在几行内
- 罗列一堆备选方案让用户自己选。有推荐就直接给推荐，再补一句代价
- 结尾写「总结」段重复一遍上面说过的话
